## Critical gotchas — read before touching anything

### Codegen bugs in cryoc itself (work around, don't depend on)

1. **`format("…%s%s…", a, b)` corrupts the second arg.** Cryoc's `format` lowers to a single shared static buffer; chained multi-arg formats clobber prior results. Workaround: split into single-arg `format` calls and concatenate with `+`. See `mangled_name.cryo::encode_ident` (uses `format("%lld%s", …)` only because that single combo happens to work — use `snprintf`-into-malloc'd-buffer for anything more complex; see `u64_to_decimal`).
2. **`string.length()` and `string.substring(start, len)` methods are unreliable.** They returned wrong byte counts and empty substrings during testing. Use libc intrinsics directly: `strlen(text)` and `substr(text, start, len)` (both declared in `stdlib/core/intrinsics.cryo`). The original mangler hit this too — `mangled_name.cryo::split_double_colon` was rewritten to use `substr` after the methods returned empty results.
3. **String concatenation chaining** (`a + b + c + d` with function calls in the middle) sometimes triggers the codegen `E0615_BINARY_OPERATION_ERROR`. Break into sequential `buf = buf + part` statements.

### Don't roll your own mangling

Every name-mangling-related computation goes through `MangledName::*` factories or the helpers in `decl_index.cryo`. There were three sites that did inline `format("%s_%s", base, arg)` for "specialized identifier" before they got centralized — sema, specializer, decl_index. If you need a new mangling scenario, add a factory to `mangled_name.cryo`, don't reinvent.

### Receiver convention

- `&this` parameter → reference receiver. Encoded as `$s` (immutable) or `$m` (mutable from the `mut` keyword on the param).
- `this` parameter → by-value receiver. Encoded as a regular first parameter (no `$s`/`$m`).
- Non-static method with no explicit receiver → implicit `$s`.

`method_receiver_kind` and `method_non_receiver_params` (in `decl_index.cryo`) are the single source of truth. Call them, don't re-implement the AST walk.

### Don't touch the type-system files looking for `mangled_name()` virtuals

They were deleted intentionally (`Type`, `IntType`, `FloatType`, `PointerType`, etc.). The new mangler is arena-driven via `encode_type` in `mangled_name.cryo`. If you see code calling `t.mangled_name()`, that's a bug.

## What NOT to do

- **Don't** start by reading every `.cryo` file. Read the memory files and this handoff first; they tell you where the load-bearing logic lives.
- **Don't** rebuild stdlib with cryoc until you've confirmed cryoc can compile a single stdlib module without hitting another stub. It'll be a long debug cycle if cryoc's monomorphization codegen has gaps.
- **Don't** add `__asm__` aliases for v0.2-mangled symbols in `cryort.c`. GAS rejects `-` in symbol names. Use the LLVM IR path (`cryort_stubs.ll`).
- **Don't** assume cryoc's standard library methods (`string.length()`, `string.substring(…)`) work correctly. They have known codegen bugs. Use libc intrinsics (`strlen`, `substr`) directly in compiler code.
- **Don't** delete the speculative factories in `mangled_name.cryo` (`for_constructor`, `for_destructor`, `for_operator`, `for_trait_impl`, `for_closure`, etc.) even though they have no callers. They're spec API surface the user asked for ahead of language features.
