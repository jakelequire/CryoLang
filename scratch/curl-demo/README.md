# curl-demo

A scratch project that vendors **libcurl** — a markedly more complex C library
than SQLite — and drives it headlessly.

It fetches a local file over curl's `file://` protocol (deterministic, no
network) and verifies the bytes, exercising two things the SQLite demo did not:

- **Variadic FFI** — `curl_easy_setopt(handle, option, ...)` is variadic in C and
  is called three times here with three *different* value types (a `string` URL,
  a **function pointer**, and a `void*`), all through the variadic ABI.
- **A Cryo function as a C callback** — `write_cb` is passed as
  `CURLOPT_WRITEFUNCTION`; curl invokes it (a Cryo function as a raw C function
  pointer) for each chunk of data.

## The generated binding

`bindings/Curl.cryo` was generated by `cryo vendor` from `curl/curl.h` — no
hand-written FFI. From that one umbrella header it bound **93 functions, 22
structs, 39 enums, 271 consts**, including the opaque `CURL*` handle (→ `void*`),
the `CURLoption` / `CURLcode` enums, and the 26 callback function-pointer types.

The translation report flagged **17 not bound / 3 approximated / 18 ignored** —
all macro-valued constants and function-like macros, never silently dropped.

## Vendoring a system library: the one wrinkle

curl's headers live under `/usr/include/...`, and the importer's system-header
filter intentionally drops decls in system paths (you don't want `stdio.h`
bound). So the headers were **copied into the vendor dir** before generating, the
same workaround the SQLite demo used for `sqlite3.h`. (A first-class "treat this
include tree as project headers" knob would remove this step — a noted follow-up
for the vendor system.)

## Running it

```sh
cd scratch/curl-demo
cryo run
# -> libcurl <version> fetched 40 bytes via file://:
#      Hello from libcurl, vendored into Cryo!
```

`-lcurl` (in `[link]`) is what the vendor registry would otherwise inject. As
with sqlite-demo, the `.cryo` binding is checked in only so you can read it; the
real workflow generates it per machine into the cache and resolves it via
`import vendor::Curl`.
