# D32's residue: every name-keyed read in `compiler/src`, classified

The completion criterion for merging `naming-impl` (`docs/name-resolution.md`
§0.1 D32, §8.276): **zero name-keyed reads outside an enumerated, justified
residue, pinned by count.** This file is the enumeration. It is one list;
every site carries its class and a one-line reason, and the J rows are the
residue Jake rules on.

## How the list is made, and how it is checked

* **The population is derived, not recalled.** `residue.py` builds it from
  `scripts/lane-gate.py`'s own parser - the stores rule 1 places, the array
  owners rule 1b places as *a member table inside its owner*, rule 2's
  signature test narrowed to a key type in PARAMETER position on a read
  (`&this` or static), and the receiver placed by its declared type (a
  dotted receiver by its annotation, a cast receiver by the type the cast
  names, a static by its spelled owner, turbofish included). A
  reader added under any spelling on any store is in the population the
  moment it is declared; a type excluded by the gate for holding paths,
  flags, texts or a pass's own rib (`DiagSink`, `ParsedArgs`,
  `ProjectConfig`, `AsyncLower`, ...) holds no declaration and is outside.
  **The same read written INLINE is a site too** (rule 1c): a loop that
  compares an array element's key-typed field with a spelling -
  `st.methods[i].name.equals(n)`, a local bound to the element
  (`const m: MethodNode* = d.methods[i]; .. m.func.name.equals(n)`), a
  `.name.id ==` compare, an array of bare names (`names[i].equals(n)`), a
  LOCAL array of records (`slots[ki].name.equals(n)`) - is the door's body
  written at the caller, and it was invisible while the population was
  method calls alone. The gate places every scanned (owner, array) as a
  TABLE (a declaration table by leaf: in the population, the row's read
  spelled `Owner::field[]`, a local table `local::Elem[]`) or as DATA
  (texts, flags, paths, triples, a dedupe set: outside), and refuses one
  in neither; a scan in the owner's own file is the door's body, as a
  store's own calls are.
  `python scripts/ns-migration/residue.py --count` is the size;
  without a flag it prints every site as `file`, `line`, receiver type,
  method, argument text.
* **The classes are judgement, held as code.** `residue_classify.py` maps
  each read METHOD to a class and a reason, with a per-site override where
  one call's key comes from somewhere the method's other callers' do not,
  and writes the table below. A method it classifies that the tree no
  longer declares, a read method the tree calls that it does not classify,
  or an override matching no call, each refuse the run.
* **The check.** `python scripts/ns-migration/residue.py --check` matches
  the table to the tree by (file, method, key text) - a line shift is not
  drift, a site added, removed or re-keyed is - and re-derives every row's
  class from `residue_classify.py`, refusing a row whose letter is not the
  classifier's (flipped, blanked, or a letter the classes do not include);
  on OK it prints the count per class from the classifier, so the number
  §0 pins is checked against the tree, the list and the code that decides
  it. A check that read the letters as written let a J row flipped to N by
  hand pass with J one lower. It also refuses a call to a population name
  that no receiver pattern reaches (a parenthesized receiver, a call with
  arguments), and pins the *elsewhere* table below. `residue_selftest.py`
  (`make residue-selftest`, in `check-fast` and CI) drives each refusal
  through a throwaway tree and list. §0's D32 row carries the command and
  the counts.
* The table is regenerated by `python scripts/ns-migration/residue_classify.py`;
  a run that changes a row's class is a change of judgement and goes in
  the ledger with its reason.

## The classes

| class | meaning | in the residue? |
|---|---|---|
| **J** | **justified** - name-keyed by design; the sub-kind is the reason's first word: `member` (a member's leaf inside a settled owner - Rust's field and method lookup is name-keyed off the owner too), `lang` (a declaration the language names by its own spelling and claims at declaration - Rust's lang items are keyed by the attribute's string), `module` (a module by its namespace path - the module graph is the declaration of modules and a namespace names exactly one, D5), `prim` (a primitive by the spelling its `Res::PrimTy` stamp carries), `extern` (a C symbol by its link name), `hint` (a did-you-mean whose question is the spelling) | **yes - these are the count** |
| N | not a key - the string names no declaration: a diagnostic label beside a `DefId`, a file path, a literal's text, a constructor's source file, a write onto an AST node, a funnel's own forwarding body. In the population because the gate's parameter test cannot tell a label from a key | no - outside D32 |
| S | stamp-derived - an index or funnel door keyed by a canonical string the caller derived from a stamp or a `TypeRef`. Convertible: the door can take the stamp | no - convertible, remaining work |
| B | the `GenericRegistry` keyed by the canonical string of a stamped identity - bucket B's reader side (§8.245); re-keying the registry by identity is Jake's unit | no - convertible, Jake's unit |
| C | a key composed from parts (`owner::member`, a family string, `ns::name`) - bucket C, behind pin-as-declaration | no - convertible, blocked |
| F | visibility asked by the callee's name (`enforce_callee_visibility`) - bucket F, behind pin-as-declaration | no - convertible, blocked |
| W | a written spelling with no stamp behind it and no reason above | no - must convert |

**The migration is complete when S, B, C, F and W are all 0 and J is at or
below the ceiling Jake sets.** The J sub-kinds are separable: if `module`
(a module by its path) or `lang` (a language-named declaration by its
spelling) is ruled NOT by design, the rows are already grouped for it and
the ceiling moves down by that sub-kind's count; nothing here pads or
trims toward a number.

Two shapes the ledger named for this list before it existed, and where
they landed: the member table inside its owner (`ImplBlockNode::lookup_assoc_binding`,
`ResolutionContext::lookup_assoc_binding`, `TraitType::get_method`) is J
`member` - `get_method` has no caller outside its file, so it has no row;
`TemplateEntry.param_names`' spelling compares in `call_resolver.cryo`
are `equals` calls on an array, not a method of a holder, so they are not
in this population - they are §8.275's arena unit and retire with it.

A third shape the first list could not see: the member tables of the
user-defined types themselves. `StructType.fields: FieldInfo[]`,
`ClassType.methods: MethodInfo[]`, `EnumType.variants: EnumVariantInfo[]`
and `TraitDeclNode.assoc_types` are arrays of RECORDS with the name in
each, searched by `rows[i].name.equals(n)` - neither a map nor an array
of names, so no rule reached them and their 43 callers were nobody's.
The gate's rule 1b now takes an array of records carrying a key-typed
field as a candidate (37 owners on this tree, 20 placed as exclusions by
reason, four of them member tables), and those callers are J `member` -
a struct's field or method, an enum's variant, a trait's associated type,
each by its leaf off the type already in hand - or J `lang` where the leaf
is one the language fixes (`__call__`, `Ready`, `Ok`/`Err`, `Some`/`None`).

## Elsewhere: population names on types that hold nothing

Every dotted call to a population name whose receiver is placed on a type
that is NOT a holder, per (type, method). These are not sites - the type
holds no declaration - but they are pinned, because a holder the placement
rule misreads as another type lands here and nowhere else; this is the
lane gate's LOOKUP_LOCAL row, by name. A static call's owner is spelled and
cannot be misplaced, so statics on non-holders are not tallied. When a row
here moves, either a receiver was misplaced (place it) or a same-named
method on an unrelated type gained or lost a caller (regenerate, and say
which in the commit).
